# TV season and permanent library downloads — October 3, 2026

The TV catalog now offers Download season for a complete, numbered season. Each episode needs independently verified work/unit evidence and the requested audio evidence before transfer. Native direct files and supported finite HLS/DASH use the same checked local download path. Websites are not accepted as download success. The operation stops at the first missing or failed episode, retains completed files, and reports the completed count.

## Problems and repairs

The catalog had no completed TV season action, and its permanent download action could not save playlists. Permanent publication now copies the checked video and owned captions into a unique staging directory, writes bounded local identity metadata, then publishes the directory atomically. Movie, season and episode identities remain separate. Existing revisions and user files are never overwritten. Temporary player leases cannot delete published permanent files. Metadata contains no stream URL, cookie or authorization header.

Restarting Download season checks completed local episodes against the selected canonical work/unit and requested audio evidence, checks recorded size when available and probes readable media before reuse. It does not make the user redownload completed episodes. Active incomplete transfers restart; this is not automatic queue recovery or partial-byte resume. Unknown audio cannot satisfy a specified language.

Downloads previously opened a saved episode through a plain filename callback, losing the canonical resume identity and local captions. It now lists the saved work/season/episode and passes the metadata context, captions and honest audio notice to an independent native player. Ordinary local files and book routing remain supported. Exact GUID staging directories are excluded while publication is incomplete.

The first live season attempt exposed an empty media resource in episode 2. Playlist body reads now retry empty/truncated bodies at most three times, closing streams and removing only the current owned partial before retry. Discarded bytes still count against the transfer budget. A persistent incomplete resource may try at most two other renditions advertised by the same matched master, with exactly the same audio/subtitle/closed-caption/video groups. It never invents URLs or omits missing segments.
