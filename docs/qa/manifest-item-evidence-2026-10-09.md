# Configured Movie/TV source evidence — October 9, 2026

## Actual problem and repair

The existing JSON-index provider parsed title/year/unit metadata but omitted `AudiovisualSource.Evidence`. Consequently, its progressive resolver could discover an exact item while reporting `independent_identity_missing` and never publishing it as ready. It also combined provider-wide supported languages with item languages, so an item without an audio declaration acquired an English claim. Two targeted production-resolver regressions reproduced both faults before the repair: **two failures, zero passes/skips, 77 ms**. The first test build hit the project's xUnit assertion analyzer; correcting the assertion overload allowed the actual reproductions. That compilation failure was not a runtime result. [Before result](C:/Users/user/animeapp/UniversalMediaOS.Tests.E2E/TestResults/manifest-evidence-before-20261009.trx).

The adapter now retains the independently returned item identity, exact unit and per-item audio/subtitle declarations through the existing evidence matcher and progressive source API. It preserves IMDb plus namespaced primary/external IDs; conflicting observed IDs reject the item, while a valid shared ID can establish a match without a year. No requested title, ID, year, unit or language is copied into matching evidence. A sole provider category remains a discovery hint when the item lacks its own kind, and that candidate stays unverified. Explicit request-echo/unknown provenance remains unverified. An unrecognized explicit content form, such as trailer, no longer becomes a feature by fallback. Specials require per-item establishment and cartoons require per-item animation evidence.

Audio comes from the item's audio declarations or the existing JSON-index media-language fields. Provider-wide languages, original-language metadata and subtitle declarations cannot supply audio evidence. Explicit audio fields take precedence over legacy language fields; `und`/`unknown` remain unknown. This is declaration evidence, not confirmation of spoken audio, available timed caption bytes or full-duration content. Existing host restrictions, request coordination/cancellation, content-type handoff and source transport rules remain.
