Numeric rate-limit backoffs were unbounded, and provider-owned timeouts could be described as caller cancellation.

The service now requires an actual media array; a valid empty array still establishes no results. Missing/incomplete pages fail instead of publishing absence. The view retains current cards and their original AniList/MAL identities, distinguishes unavailable lookup from confirmed emptiness, and stops paging an incomplete query until explicit Search restarts page one. Recommendation, keyword and page errors are guarded by the current generation. Caller cancellation remains distinct from provider timeout. A new generation invalidates retired work before canceling it, preventing its status from reaching the new query.

`Retry-After` delta/date values within the existing 20-second request budget retain the single automatic retry. Longer advertised waits return unavailable without retrying before the server permits it. This bounds automatic backoff; it does not shorten the existing HTTP request timeout. Known cards remain available and an explicit later retry is required. There is no new catalog/provider, mandatory key, persisted metadata cache or guessed identity.
