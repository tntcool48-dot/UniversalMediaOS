# Movie/TV Watch via download checkpoint — 2026-10-01

Resolved direct-file Movie/TV sources now expose **Watch via download**, **Stream**, and a separate permanent library download. Website cards retain their explicit Open website action. HLS/DASH sources offer Stream and do not advertise single-file downloading. TV's permanent direct-file action is labelled **Download episode to library**; a season-wide transfer is still unfinished.

Watch via download reuses `AuthorizedMediaDownloadService` and the existing player-tab lease handoff. It downloads to the separate app-owned `TemporaryMediaWatch` root, preserves provider request headers, checks that the response is a complete nonempty video file, and uses `ffprobe` to require readable video and audio tracks before opening the native player. Media probing does not establish the film cut, episode identity or spoken language. Unverified source cards retain their match warning in the player, and missing audio tags remain unverified.

Completed files are shared by matching work/unit/source/request context. Different remakes, seasons/episodes and source versions have separate files. Each player receives its own idempotent lease; the final owner releases the player before deleting its GUID job directory. Closing the details page leaves opened players' files alive. Cancellation, selection changes, failed verification and failed handoffs release temporary ownership. Restart cleanup removes abandoned GUID jobs while retaining active locked jobs and unrelated directories. Permanent library downloads use their existing destination and survive temporary cleanup.

The temporary path has the configured size limit (25 GiB default), a 1 GiB free-space reserve, a two-hour operation deadline, a two-minute body-read inactivity deadline and a 30-second probe deadline. Progress callbacks reject cancelled/replaced operations. Disposing details now also clears its downloading state; a focused regression exposed that it previously stayed true after cancellation.
