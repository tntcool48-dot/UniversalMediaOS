## Demonstrated problem and repair

The physical first-season Frieren detail page (AniList 154587, MAL 52991), Dub, episode 1, failed at 18:55 after receiving 75 AnimeTosho RSS results. The parser read only item links, whereas the live feed placed its magnet in a quoted link inside the HTML description. Consequently every result lacked a usable magnet. The parser now reads and HTML-decodes that magnet while retaining the Nyaa info-hash fallback. It does not choose the release website or torrent enclosure as a playable source.

Discovery also counted wrong seasons, unrelated titles, explicit later episodes, duplicates and unusable results toward fallback limits. Only distinct candidates passing the existing title, season, format, requested episode and Dub evidence checks now count. Catalog aliases remain bounded and trusted; torrent metadata must still contain exactly one file for the requested episode. Dub and dual-audio searches both run for the catalog title before ranking seeder evidence. A live Nyaa dual-audio search found a seeded first-season release that the earlier Dub-only stopping rule skipped.

The UI now exposes **Cancel download** during the temporary watch operation. Cancellation uses the existing operation token, restores action states and prevents a stale player handoff. The first visible metadata cancellation settled at 19:08:55 with no player and zero owned job folders. A later partial payload cancellation at approximately 20% also removed the whole owned job. That payload attempt exposed an unselected episode file being created before priorities were applied.

Code inspection confirmed that normal magnet startup can switch directly from metadata to payload before the app assigns file priorities. Torrent metadata is now acquired without starting payload transfer; the selected video and matching captions receive their priorities before transfer starts. This uses MonoTorrent's supported [metadata-only discovery implementation](https://github.com/alanmcgovern/monotorrent/blob/release-v3.0.2/src/MonoTorrent.Client/MonoTorrent.Client/ClientEngine.cs). Its metadata mode checks the magnet's info hash and preserves tracker tiers. Transfer shutdown and normal completion use a two-second tracker-announcement limit. The revised live cancellation at 19:26:04 immediately showed Stopped in the refreshed UI, re-enabled Watch, opened no player, and left zero owned job folders. Metadata discovery retains its 60-second operation cancellation; the library's own metadata teardown can add tracker shutdown time, which is a remaining latency qualification.
