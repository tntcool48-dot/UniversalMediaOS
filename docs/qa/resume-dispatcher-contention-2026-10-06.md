# Resume save dispatcher contention — October 6, 2026

An isolated SQLite writer reproduced inactive-tab pause stalls of **1515.582 ms for catalog media** and **1510.782 ms for legacy media**. Both tests failed their 500 ms allowance before repair. The asynchronous SQLite calls could execute their busy wait inline on the player dispatcher.

SQL saves now execute on workers after acquiring the existing ordering semaphore. Catalog saves configure their connection before yielding so a later profile/configuration change cannot redirect queued progress. Captured work/unit, owner, latest-write and completion guards remain. Legacy final saves use the same worker path with a two-second caller wait; accepted saves retain the owned database/semaphore until every pending operation ends. Closing does not discard a captured final position after that deadline.
