# Bounded native streaming requests and shutdown — October 3, 2026

## Actual problem and fix

HLS used headers-only HTTP completion followed by uncancelled manifest/key reads and an unlimited segment copy. HTTP's header timeout did not bound these bodies. Dispatch spawned unrestricted request tasks; player-session removal left active requests alive. Created-time expiry could also remove a healthy long-running session.

The shared HLS/DASH proxy now admits at most **64 sessions, 32 simultaneous requests and eight requests per session**, rejecting excess work without evicting existing players or retaining a queued task. Expiry uses four hours of inactivity and cannot expire an active transfer. Requests link both the owning session and the current listener lifetime. Source replacement/player close cancels only its sessions; stop/dispose cancels every session, closes the listener and clears registrations. Synchronous UI disposal does not wait for network work; optional asynchronous draining has a two-second ceiling.

Manifest headers/body/rewrite/output have a 20-second total deadline; key and caption files have ten seconds. HLS manifests retain the five-MiB input limit and now bound lines, line length, resource count and rewritten growth before excessive allocation. Remote URLs are bounded at 16 KiB. AES-128 keys must contain exactly 16 bytes; finite bodies must match a declared length. Playlist media has a 20-second header deadline, 20-second read/write inactivity deadline, two-minute overall ceiling and 64-MiB per-resource cap. Progress resets inactivity, while the overall deadline still applies. Interrupted/truncated relays abort instead of completing a successful corrupted response.

Full authenticated files use a distinct `/media` route with a 64-GiB/24-hour overall bound and the same header/inactivity cancellation. This preserves normal film streaming beyond a playlist segment's cap. Native seeks retain a single byte range, returned Content-Range/Accept-Ranges and exact media bytes. Existing public-network/redirect checks, origin-scoped credentials, rewritten playlist resources and mislabeled-TS packet verification remain in place. The DASH initialization compatibility repair is preserved.

## Limits

This establishes bounded proxy behavior under the checked transfers and normal player lifecycle. It does not certify all providers, slow-network/full-duration/overnight playback, spoken language, native caption switching, exact catalog DASH or packaged release behavior. Sessions idle for four hours expire; overnight paused-player recovery remains unqualified. Remote transports which ignore cancellation cannot be forcibly drained, but cannot block UI disposal or the bounded asynchronous shutdown return. Caption popup selection remains a [desktop-tool limitation](C:/Users/user/animeapp/docs/qa/downloaded-caption-check-2026-10-03.md).
